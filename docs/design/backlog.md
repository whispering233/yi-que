# 开发遗留项

本文记录已知但**有意推迟**的事项。每项须带明确的触发条件，避免遗留项变成无人处理的黑洞。

## 待验证的技术风险

| 项 | 说明 | 触发时机 |
| :--- | :--- | :--- |
| **内容页的 RSC 水合载荷** | 每个预渲染页内联约 16KB 的 `__next_f` 载荷，供客户端路由换页用。但预取文件已在构建后清理，该载荷实际不可用——**词作页 23.4KB 中只有约 1KB 是词文本身** | 站点体积接近托管上限，或部署时长成为瓶颈 |
| **静态产物体积** | 23439 个页面共 **545MB**（文件字节），而托管上限 1GB（已用 53%）。单页均 23.3KB。传输侧只有 gzip 4.4KB/页，问题在产物盘占而非带宽 | 内容增长接近上限，或需迁移托管 |
| **全量预渲染 2.3 万页是否必要** | 纯静态托管下只能在构建期全量生成。若改为有服务端的托管，按需渲染只生成被访问过的页 | 迁移到有服务端的托管时 |
| **Brotli 的可选路径** | 当前托管（GitHub Pages）**只提供 gzip**。若移动端实测不可接受，可选：自备 brotli 产物 + 浏览器端 WASM 解压（省约 610KB，代价是约 80KB WASM 与解压耗时），或换到支持 Brotli 的托管 | 移动端实测加载时长不可接受时 |

## 已推迟的功能

| 项 | 推迟理由 | 触发条件 |
| :--- | :--- | :--- |
| **L4 辨谱的界面入口** | 引擎侧已实现且有测试，但校验页只提供「选词牌 → 选词格」两级。界面入口涉及交互设计（不选词牌时如何呈现候选与置信度），不在工具站范围内 | 用户反馈「不知道自己的词是什么词牌」 |
| **L5 引擎能力**（出律改字建议、笺注、典故分析） | 需要语料统计或模型能力，是独立工程。且不改变引擎架构 | 社区阶段，或用户反馈明确要求 |
| **繁简切换** | 自动繁简转换会出错（一简对多繁：发→髮/發、后→後、余→餘）。在「鉴赏」场景下文本错误不可接受 | 需要人工校勘或按字标注的转换数据 |
| **其余韵书**（平水韵、中华通韵） | 引擎已按韵书参数化，加韵书是加数据不是改架构 | 用户反馈明确要求 |
| **其余词谱谱系**（如龙榆生《唐宋词格律》） | 覆盖面是《钦定词谱》的子集，且整理校勘成果权属存在争议 | 明确需求 + 权属问题解决 |
| **检索语料分片渐进加载** | 全量 gzip 2.91MB 一次性加载 + 缓存可接受。分片会导致「搜不到已存在的词」 | 移动端实测跳出率异常且确认归因于载荷 |
| **逐字定位输入**（桌面端辅助） | 移动端明确不做，桌面端非主路径 | 桌面用户反馈要求 |
| **社区功能**（账号、作品发布、评论、点赞、收藏） | 属于公开社区阶段，需要服务端与数据库 | 工具站验证完成 |

## 数据质量

| 项 | 说明 |
| :--- | :--- |
| **语料丢了字** | 2574 首词作与最近词格**只差 1 字**——上游转录丢了字却未标缺字标记。这使 5265 首词作找不到同字数词格 |
| **词牌归属与词谱不一致** | 部分词作的全宋词词牌名与《钦定词谱》的归类不同（如「玉楼春」与「木兰花」是相关但不同的调）。上游有 226 种词牌名未命中归一化表 |
| **异体字归一化（韵书侧）** | 剩余「待定」多为韵书里查不到的字（閒→闲、諠→喧、敧→欹、捲→卷）。需要把异体字表从词牌名归一化模块移到引擎与管道都能用的位置 |
| **作者名被截断** | 上游有 **80 位作者的名字只有一字**（李、蔡、陈、王…），描述为 `"--"`。从描述可辨认出部分（「字方叔」=李廌），但**多数无法考证**。当前原样保留并记入待核清单，用户会看到「李」这样的作者名 |
| **词谱的字位标注精度** | 词谱的句读标记含若干和声类特例，是否需在引擎中特殊处理待用例覆盖后确认 |
| **自检的例外清单** | 构建期异常共 651 条：3 条自述不可解析、75 条结构复算不一致、4 条谱式串与平仄串不一致、489 条词牌名未命中、80 条作者名被截断。清单随构建产物落盘，须人工抽核 |
| **上游持续修订** | 上游语料至今仍在校订文本。管道须支持重跑，且词作用稳定 id 保证 URL 不因修订而失效 |

## 工程负债

| 项 | 说明 |
| :--- | :--- |
| **slug 人工指定表待复核** | 词牌 3 条、作者 60 条。初稿由管道自动生成——同名重复（李 ×8、王 ×8）与同音异名无法从名字本身区分。复核时若知道确切身份可改成有意义的 slug，但**改 slug 会失效已有外链**，须按破坏性变更处理 |
| 站点备案 | 若后续迁移至中国大陆托管，需域名备案 |

## 已明确不做

以下为评估后主动排除的方向，避免日后重复讨论。

| 项 | 理由 |
| :--- | :--- |
| 纯静态 AI 生成式站点 | 无内容护城河，且与「鉴赏」定位冲突：产品的价值在于格律与语料的准确性，不在于生成 |
| 服务端格律校验 | 词谱是公有领域数据，服务端化无收益，且逐字实时反馈是核心体验，网络往返不可接受 |
| 预建倒排索引 | 在 gzip 下无收益甚至更差（原文 2.86MB、字级倒排 2.89MB、二元倒排 5.12MB），而运行时建索引仅 449ms |
| 全量中文字体下载 | 移动端不可接受（子集后仍 1.4–1.9MB），而 2.2KB 的扩展区 fallback 已覆盖实际缺口 |
| 与第二套组件/样式系统并存 | 会导致样式与断点漂移，须单一来源 |
| 逐字输入格（移动端） | 手机输入法逐字定位是灾难，整段输入更自然 |
| 字数不符时的精确诊断（缺字/衍字/漏句定位） | 中文诗词没有词边界，字级 diff 容易给出无意义的对齐。自动对齐是**猜测**，猜错会误导用户。归入 L5 |
