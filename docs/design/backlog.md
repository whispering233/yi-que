# 开发遗留项

本文记录已知但**有意推迟**的事项。每项须带明确的触发条件，避免遗留项变成无人处理的黑洞。

## 待验证的技术风险

| 项 | 说明 | 触发时机 |
| :--- | :--- | :--- |
| ~~静态导出下的样式抽取~~ | **已解除**——实测 antd 样式被构建期完整抽取。约束与实测数据见 `architecture.md` | ✅ 已验证 |
| **内联 CSS 的体积与跨页缓存** | antd 抽取的样式**内联进每个页面**（88.4KB 原始 / gzip 12.1KB），不可跨页缓存。数千个预渲染内容页会重复传输同一份样式。须评估是否改用构建期静态样式抽取方案，或压缩内容页的 antd 组件用量 | 内容页规模上去后（卡 17 前后） |
| **antd 复合组件强制页面成为客户端组件** | 使用 antd 复合组件的页面必须标 `"use client"`（原因见 `architecture.md`），这会增加这些页面的 JS 体积并失去服务端组件优势。须评估能否改用基础组件以保持服务端渲染 | 卡 15–17 |
| ~~Brotli 实测收益~~ | **已实测**：当前托管（GitHub Pages）**只提供 gzip，不支持 Brotli**——请求 `br` 返回未压缩内容，比 gzip 更差。载荷预算已改为按 gzip 计（词谱 581KB、语料 2.77MB） | ✅ 已验证 |
| **若需 Brotli 的可选路径** | gzip 比 Brotli 多 24%–34%（词谱 +195KB、语料 +690KB）。若移动端实测不可接受，可选：自备 brotli 压缩产物 + 浏览器端 WASM 解压（省约 610KB，代价是约 80KB WASM 与解压耗时），或换到支持 Brotli 的托管 | 移动端实测加载时长不可接受时 |

## 已推迟的功能

| 项 | 推迟理由 | 触发条件 |
| :--- | :--- | :--- |
| **L5 引擎能力**（出律改字建议、笺注、典故分析） | 需要语料统计或模型能力，是独立工程。且不改变引擎架构 | 社区阶段，或用户反馈明确要求 |
| **繁简切换** | 自动繁简转换会出错（一简对多繁：发→髮/發、后→後、余→餘）。在「鉴赏」场景下文本错误不可接受 | 需要人工校勘或按字标注的转换数据 |
| **其余韵书**（平水韵、中华通韵） | 引擎已按韵书参数化，加韵书是加数据不是改架构 | 用户反馈明确要求 |
| **其余词谱谱系**（如龙榆生《唐宋词格律》） | 覆盖面是《钦定词谱》的子集，且整理校勘成果权属存在争议 | 明确需求 + 权属问题解决 |
| **检索语料分片渐进加载** | 全量 2.08MB 一次性加载 + 缓存可接受。分片会导致「搜不到已存在的词」 | 移动端实测跳出率异常且确认归因于载荷 |
| **逐字定位输入**（桌面端辅助） | 移动端明确不做，桌面端非主路径 | 桌面用户反馈要求 |
| **社区功能**（账号、作品发布、评论、点赞、收藏） | 属于公开社区阶段，需要服务端与数据库 | 工具站验证完成 |

## 数据质量

| 项 | 说明 |
| :--- | :--- |
| 上游残留乱码 | 上游修订版仍有非缺字类乱码，分散在个别词作中，每处出现 1–3 次。管道须清理；**考证不出的须标为缺字**（不原样保留），并维护待核清单 |
| 缺字词作的呈现 | 缺字标记所在的字位不得计入出律，也不得落进「待定」。界面须有统一的缺字呈现 |
| 词牌别名完整性 | 别名映射表来自第三方数字化成果，其许可与完整性须核验。核验不足时须以《钦定词谱》原典自建 |
| 词谱的字位标注精度 | 词谱的句读标记含若干和声类特例，是否需在引擎中特殊处理待用例覆盖后确认 |
| **自述字段污染** | **实测 164/2475（6.6%）的词格自述是「定格」「双调」「格一」这类无法解析的值**，可用率仅 93.4%。这些词格无法参与结构复算自检，须进待核清单 |
| **「定格」标注与位置不自洽** | 上游 137 个词格的自述字面为「定格」，其中 124 个位于所在词牌的末体；且存在末体与首体字位序列不同的情形。**正体不能据此判定**，须取自原典体例（第一个词格） |
| **空词牌** | 上游有 1 例词格数为 0 的词牌（「清平调辞」）。管道须排除或标注 |
| **词格重复** | 实测 18 处词格的字位序列与同词牌内前一体完全相同，须去重 |
| 上游持续修订 | 上游语料至今仍在校订文本。管道须支持重跑，且词作用稳定 id 保证 URL 不因修订而失效 |

## 工程负债

| 项 | 说明 |
| :--- | :--- |
| 拼音表缺字 | 所需真汉字中有 1 字（扩展区）不在拼音表中，中华新韵无法判定其平仄。须有明确的降级路径 |
| 字体源文件 | 字体子集化需要源字体，源字体体积大且不入版本控制。构建环境的字体获取方式须确定 |
| 词牌 slug 多音字 | 冲突须人工指定，指定表须随管道一同维护 |
| 站点备案 | 若后续迁移至中国大陆托管，需域名备案 |
| 依赖许可核验 | 数据源许可已逐一核实，但**词谱别名表**的许可尚未确认 |

## 已明确不做

以下为评估后主动排除的方向，避免日后重复讨论。

| 项 | 理由 |
| :--- | :--- |
| 纯静态 AI 生成式站点 | 无内容护城河，且与「鉴赏」定位冲突：产品的价值在于格律与语料的准确性，不在于生成 |
| 服务端格律校验 | 词谱是公有领域数据，服务端化无收益，且逐字实时反馈是核心体验，网络往返不可接受 |
| 预建倒排索引 | 体积大于原文（二元组索引 5.19MB vs 原文 2.08MB），运行时建索引仅 449ms |
| 全量中文字体下载 | 移动端不可接受（子集后仍 1.4–1.9MB），而 40KB 的扩展区 fallback 已覆盖实际缺口 |
| 与第二套组件/样式系统并存 | 会导致样式与断点漂移，须单一来源 |
| 逐字输入格（移动端） | 手机输入法逐字定位是灾难，整段输入更自然 |
| 字数不符时的精确诊断（缺字/衍字/漏句定位） | 中文诗词没有词边界，字级 diff 容易给出无意义的对齐。自动对齐是**猜测**，猜错会误导用户。归入 L5 |
