# 架构

本文说明技术栈选型、核心架构理念、分包方案与包依赖链。选型的量化依据见 `docs/research/competitive-analysis.md`。

## 技术栈选型

| 层 | 选型 | 理由 |
| :--- | :--- | :--- |
| 语言 | TypeScript | 格律引擎须在前端逐字实时运行；同语言使引擎、管道、UI 共用一套领域类型 |
| 框架 | Next.js（App Router） | 词作详情页是 SEO 主力资产，需要构建期预渲染；静态导出即可发布，零服务端成本 |
| UI 组件 | antd v6 | 中文原生设计语义（组件元数据双语、设计标度为中文排版校准）；官方 CLI 提供离线版本化元数据与 MCP 接口，AI 可查真实 props 而非凭记忆；`antd design.md` 直接产出 `@google/design.md` 规范的 token 源 |
| 样式 | Tailwind CSS | 只管布局（flex/gap/grid/断点）；颜色与排版一律走 antd token，不并存第二套样式系统 || 数据 | 静态 JSON 产物 | 全部语料与词谱体积经实测可在客户端承载，无需服务端 |
| 检索 | 客户端运行时索引 | 语料 gzip 后 2.93MB，浏览器运行时建二元索引 449ms；无服务端、离线可用 |
| 后端（B 阶段） | PostgreSQL + Drizzle | 社区功能（账号、作品、评论）才需要；C 阶段不引入 |

## 核心架构理念

### 一、静态优先，服务端是 B 阶段的事

C 阶段（工具站）**纯静态导出**，无服务端、无数据库、无运行时 API。全部数据在构建期由管道产出，页面由构建期预渲染。

这条不是省钱，是**消除一整类故障**：没有服务端就没有服务端宕机、无冷启动、无并发上限、无运维。用户打开即可用，检索在本机跑。

### 二、引擎是纯函数层，与框架完全解耦

格律校验引擎是产品的技术核心，它必须满足：

- **零框架依赖**——不得引用 React、DOM、Next.js、Node API
- **零网络依赖**——输入词牌与词作文本，输出判定结果，全同步
- **数据驱动**——行为由词谱与韵书数据决定，不硬编码任何词牌

满足这三点的直接收益：同一份引擎代码可被浏览器直接调用（C 阶段的实时校验），未来也可被服务端、CLI、测试脚本调用（B 阶段），**不需要重写**。

词谱与韵书是**数据**，不是代码。加一本韵书、加一个谱系都是加数据源，不是改架构。

### 三、单一来源（Single Source of Truth）

项目中有四处天然容易出现「两套并存」的地方，逐一收口：

| 易漂移点 | 收口方式 |
| :--- | :--- |
| 领域类型 | `schema` 包是唯一来源，其余包一律引用，不得各自声明 |
| 设计令牌 | antd token 是唯一来源，Tailwind 只管布局；`docs/ui/DESIGN.md` 是 token 的文档镜像 |
| 响应式断点 | 单一常量定义，Tailwind `screens` 与 antd `ConfigProvider` 均从它派生 |
| 词牌名 | 归一化映射表是唯一来源（别名、繁简、分隔符），引擎与检索均消费同一份 |

### 四、数据管道有护栏，上游错误不进产品

上游语料已知含乱码、缺字标记、词牌名格式不一。管道必须**在构建期把问题暴露出来**，而不是让用户看到。

管道产出前强制执行自检：词格字数与韵位/句读数量须与词谱自述（如「前段三句三平韵」）一致；词牌 slug 唯一性；缺字与异常字符计数须在已知白名单内。任一不通过即构建失败。

## 分包方案

逻辑包按职责划分，**包内文件结构以代码为事实源，本文不描述到文件级**。

| 包 | 职责 | 依赖 |
| :--- | :--- | :--- |
| `schema` | 领域类型的唯一来源：词牌、词格、字位、词作、词人、韵书、校验结果 | 无 |
| `core` | 纯函数领域层：格律校验（对谱、韵位、多音字消歧、变格、自动辨谱）、韵书查询、文本归一化 | `schema` |
| `corpus` | 读取构建产物为领域类型；词牌名归一化映射；检索语料的加载与索引 | `schema` |
| `ui` | 可复用组件层：antd 封装基座 + 领域自定义组件（平仄字块、词谱谱式、词作排版） | `schema` |
| `app` | Next.js 路由、页面、布局、元数据 | `corpus`、`core`、`ui` |
| `scripts` | 构建期数据管道（仅构建期运行，不进运行时打包） | `schema` |

### 包依赖链

```
scripts ──→ schema
              ↑
            core
              ↑
corpus ──→ app ──→ ui
              ↑
            core
```

**硬约束：**

- `schema` 不依赖任何包
- `core` 不得依赖 `ui`、`app`、`corpus`，不得引用 React / DOM / Next.js / Node API
- `ui` 不得依赖 `app`、`corpus`、`core`
- `scripts` 不得被任何运行时代码引用

违反上述任一条即为架构破坏，须在评审时拦下。

## 关键技术约束

### 静态导出边界

Next.js 的静态导出模式会禁用 Route Handler 与 Server Action。因此：

- C 阶段所有取数一律通过静态产物，**不写任何服务端逻辑**
- 页面若引用请求期能力，静态导出会直接构建失败——这是约束生效的机制，不是需要绕开的障碍
- B 阶段引入服务端时，因取数逻辑集中在 `corpus` 而判定逻辑集中在 `core`，改造面限于新增服务端代码与数据层，**不需要重构现有页面**

### 样式层叠：Tailwind 无法覆盖 antd（实测）

**Tailwind v4 的工具类位于 `@layer utilities`，而 antd 的 CSS-in-JS 样式未分层。按 CSS 规范，未分层样式优先于分层样式，与特异性无关。**

实测：`<Tag className="sm:hidden">` 的类名确实在 DOM 上，但计算出的 `display` 仍是 antd 的 `inline-block`。

**推论**：**Tailwind 工具类只能写在原生元素上。** 写在 antd 组件上时，只要该属性被 antd 自己的样式设置过，就会静默失效。

需要给 antd 组件加布局时，用原生 wrapper 包一层，或改用组件自身的 API。

### 响应式断点：antd 的不可配置（实测）

antd v6 的断点硬编码在主题内部（`aliasToken` 先展开用户 token、再被硬编码值覆盖），**实测无法通过 `theme.token` 覆盖**（对照组：同一处传 `colorPrimary` 生效）。

且其取值与 Tailwind 不一致：

| | sm | md | lg | xl | xxl |
| :--- | :--- | :--- | :--- | :--- | :--- |
| antd（硬编码） | 576 | 768 | **992** | **1200** | **1600** |
| 本项目（Tailwind 标度） | 640 | 768 | 1024 | 1280 | 1536 |

**约束：禁用 antd 的响应式 API**（`Row`/`Col` 的断点 props、`Grid.useBreakpoint`）——它们会用 576/768/992/1200 这套值。响应式布局一律走 Tailwind；JS 侧需要断点判断时用 `useBreakpoint`（消费同一份断点常量）。

### 引擎能力分层

引擎能力按 L1–L4 分层交付，L5 后置。分层定义、判定语义与降级策略见 `docs/design/10-prosody-engine.md`。

### antd 与 React 服务端组件的边界（实测）

antd v6 的组件文件自带 `"use client"` 指令，因此**从服务端组件里直接 import antd 组件是可行的**。但有一条硬约束：

**antd 的复合组件（如 `Typography.Title` 这类属性访问）在服务端组件里取不到。** 服务端组件从客户端模块导入得到的是**客户端引用代理**，它只能作为 JSX 元素类型使用，不暴露子组件属性。实测表现为构建期预渲染报 `Element type is invalid ... got: undefined`。

**约束：任何使用 antd 复合组件的页面或组件，必须标 `"use client"`。** 纯 antd 基础组件的服务端组件用法不受影响。

### 样式抽取的代价（实测）

antd 的 CSS-in-JS 在构建期被抽取并**内联进每个静态页面**：

| 项 | 原始 | gzip |
| :--- | :--- | :--- |
| antd 内联 CSS（单页） | 88.4KB | 12.1KB |
| Tailwind 外链 CSS | 6.1KB | 2.1KB |
| 完整页面 HTML | 106.4KB | 17.8KB |

**内联 CSS 不可跨页缓存**。对数千个预渲染的内容页而言，这意味着每页都重复传输一份 antd 样式。这是内容规模上去后需要评估的项，已记入 `backlog.md`。

- 网络服务形态下必须向用户提供对应源码入口
- 依赖许可须与 AGPL 兼容：当前全部依赖（Next.js、React、antd、Tailwind）与数据源（语料、拼音表）均为 MIT 或公有领域
