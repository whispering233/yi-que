# 领域数据结构

本文定义项目的领域模型：有哪些实体、各自承载什么、形态如何分层。

引擎的**行为**（能力分层、消歧手段、判定语义）见 `10-prosody-engine.md`；数据的**来源与清洗**见 `20-corpus-pipeline.md`。本文只描述**形状**。

## 一、形态分层

领域数据有两层形态，边界是明确的。

| 层 | 消费者 | 特征 |
| :--- | :--- | :--- |
| **存储形态** | 浏览器加载 | 体积优先。字符串编码，逐字符承载信息 |
| **领域形态** | 引擎、UI | 可读、可测、类型明确 |

管道产出存储形态；`corpus` 包在加载时解码为领域形态，**一次性完成**（全部词格合计不足二十万字位，浏览器内是毫秒级）。

**为什么分两层**：

1. **引擎可读可测**——纯函数层消费领域对象才能写出清晰的单测。让引擎直接啃编码字符串会把引擎耦合到编码格式，**改编码就会波及引擎**
2. **解码量很小**——不需要惰性解码，省下的时间不值得引入缓存状态与失效问题
3. **边界清楚**——改编码只动 `corpus` 与管道，引擎不受影响

代价是同时维护两套类型。但存储形态的类型极简（就是字符串），不构成负担。

## 二、实体清单

```
词牌 ──1:N──→ 词格 ──1:N──→ 字位
                              ↑
词人 ──1:N──→ 词作 ───────────┘（校验时按位对应）

韵书 ──1:N──→ 韵部
       └─1:N─→ 字音 ──引用─→ 韵部

校验结果 ──1:1──→ 候选词格（有序）
         └─1:N─→ 字位结果 ──引用─→ 字位
```

| 实体 | 一句话 |
| :--- | :--- |
| 词牌 | 曲调。一个词牌有多条别名，下有多个词格 |
| 词格 | 词牌的一种格式。由有序的字位序列构成 |
| 字位 | 词格中的一位。承载平仄要求、句读标记、换片标记 |
| 词作 | 一首词。引用词牌与词人，正文为原样字符串 |
| 词人 | 作者 |
| 韵书 | 韵部体系。是字音条目的容器 |
| 韵部 | 一个韵类 |
| 字音 | 一个字的一种读法。承载平仄、韵部、可选读法标签 |
| 校验结果 | 一次校验的产出 |
| 字位结果 | 一个词格字位的校验结果 |
| 候选词格 | 一个可能匹配的词格及其匹配度 |

## 三、两个正交维度（贯穿全模型的核心概念）

模型中有两处必须严格区分「**判定**」与「**输入状态**」，混淆会导致语义污染。

### 字位层面

| 维度 | 取值 |
| :--- | :--- |
| **字位内容** | 未填 / 缺字 / 已填某字 |
| **判定态** | 合 / 出律 / 待定（**仅「已填某字」时有值**） |

**判定态恒为三值，不得出现第四态。**

- 「未填」是**输入状态**，不是判定。逐字实时校验下它**是常态**——用户填到一半就会看结果
- 「缺字」也是输入状态。原文此处无字，任何判定都是编造：它不「合」、不「出律」、也不「待定」，而是**无判定**
- 「缺字」不得落进「待定」。后者的定义是「多音字，需人工确认读音」，让缺字混进去，用户会以为系统要他确认一个不存在的字的读音

### 整篇层面

| 维度 | 取值 |
| :--- | :--- |
| **整体结论** | 合律 / 出律 / 无法判定 |
| **各计数** | 出律 / 待定 / 缺字 / 未填 的字数 |

同一原则：整体结论**不含输入状态**。

- 「未填」不进入结论。写进去会让这个字段在多数时刻都显示「未填完」，没有信息量
- 「缺字」使结论无法完整给出——原文缺失，无从判定。所以「无法判定」是正确的**结论值**
- 结论由**引擎单点给出**，不由 UI 从计数推导。否则校验页、分享卡片、未来的作品页会各自推出不同结果

## 四、逐实体字段

### 词牌

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 正名 | 是 | 归一化后的名称，用于匹配 |
| 别名 | 否 | 别名集合，用于检索与匹配 |
| 简介 | 否 | 词谱原典的词牌源流说明 |
| slug | 是 | URL 标识。**唯一且稳定**，不得因内容修订而变 |
| 词格 | 是 | 该词牌下的词格序列 |

### 词格

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| id | 是 | `{词牌 slug}-{字位数}-{同字数内序号}`，见下 |
| 是否正体 | 是 | **独立字段**，取自原典体例，不由 id 或自述推断 |
| 字位数 | 是 | 从字位序列复算 |
| 自述 | 否 | 词谱原文的结构描述（如「双调九十五字，前段九句四平韵」）。**实测可解析率 93.4%** |
| 例词作者 | 否 | 词谱举例所用的词人 |
| 字位序列 | 是 | 有序 |

**id 的构成**：`{词牌 slug}-{字位数}-{同字数内序号}`，如 `bu-suan-zi-44-1`。

序号 = **在同一词牌下、字数相同的那些词格当中，按原典顺序排第几**。

```
卜算子 原典 9 体，字数 44,44,44,45,45,45,46,46,46

  原典序    #1    #2    #3    #4    #5    #6    #7    #8    #9
  字数      44    44    44    45    45    45    46    46    46
            └── 44 字组 ──┘└── 45 字组 ──┘└── 46 字组 ──┘
  组内序号    1     2     3     1     2     3     1     2     3

  id      bu-suan-zi-44-1   bu-suan-zi-44-2   bu-suan-zi-44-3
          bu-suan-zi-45-1   bu-suan-zi-45-2   bu-suan-zi-45-3
          bu-suan-zi-46-1   bu-suan-zi-46-2   bu-suan-zi-46-3
```

**为什么用「同字数内序号」而非全局序号**：全局序号是数组位置，上游新增或删除一个变体，其后所有词格的 id 全部位移。字数是从字位数据算出来的，重跑管道不会变；序号被限定在字数组内，漂移面被压到最小。

**它不消除漂移，只把漂移关进一个字数组里。** 因此产物须附**词格 id 清单入库**，构建时逐条比对：id 消失或指向改变即**构建失败**——那意味着外链失效与数据库引用断裂。

**序号是位置标签，不承诺语义。** 它不表示「第 N 体」，也不表示重要性。正体由独立字段表达。

### 字位

| 字段 | 必选 | 取值 |
| :--- | :--- | :--- |
| 平仄要求 | 是 | 平 / 仄 / 中（中＝平仄皆可，不判定） |
| 句读标记 | 是 | 句 / 读 / 韵 / 叶 / 叠 / 换 |
| 换片标记 | 否 | 标在该片最后一个字位 |
| 和声标注 | 否 | 词谱中「群相随和之声」的记录（如《竹枝》的「竹枝」「女儿」）。**不是结构标记，不参与判定** |

**和声与句读标记分开建模**：句读标记必须是**封闭集合**（引擎的变格逻辑按它分支，见 `10-prosody-engine.md`），而和声是任意文本。混在一起会让句读标记无法封闭，失去类型安全。

### 词作

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| id | 是 | **稳定数字 id**。URL 使用它 |
| 词牌引用 | 是 | 语料词作的词牌名经归一化后得到 |
| 词人引用 | 是 | |
| 题名 | **否** | **语料词作恒为空**——上游数据没有题名（全宋词体例中词牌即题） |
| 正文 | 是 | **原样字符串**，保留标点与排版换行 |

**正文为原样字符串的理由**：

1. **上游没有片/句边界**——两个源的「分段」都只是排版换行，不承载结构。实测：水调歌头（双调 95 字）上游 8 段；如梦令（**单调**）上游 6 段；全库段数分布 1 段至 76 段无规律
2. **片边界的唯一可靠来源是词格**——词格有换片标记与每片字数
3. **推导会在出律时出错**——作者字数不符时按词格切分就会切错。若把推导固化进存储，等于把错误固化；按需推导则错误只出现在那一次校验结果里，**不污染原始数据**
4. **排版换行保留但无结构语义**——它直接用于展示，但**代码不得依赖它做切分**

**标点不参与对齐**。对齐的锚是「词格字数序列」。用户标点与词谱句读不一致是常见情况（作者常不标顿号级的「读」），句读位置一律由词格位次决定。

**缺字**以 `⿰` 原样保留在正文中。`⿰` 是表意文字描述符，正常宋词文本不会出现，用它当标记是安全的；不引入自定义占位符。

### 词人

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 名称 | 是 | |
| slug | 是 | URL 标识，唯一且稳定 |
| 简介 | 否 | |
| 生卒年 | 否 | 上游嵌在简介文本中，须提取 |

### 韵书

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 名称 | 是 | |
| 韵部 | 是 | 该韵书的韵部集合 |
| 字音索引 | 是 | **按字**反查。加载时从韵部方向构建 |

### 韵部

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 名称 | 是 | 如「第一部」（词林正韵）或「一麻」（中华新韵） |

**韵部不含声调——声调是字音条目的属性。**

一个韵部同时含平、仄、入声的字：词林正韵的「第一部」下就有平声（东同童…）与仄声（董懂动…）两个声部。把声调挂在韵部上会用一个声部覆盖整个韵部——**实测踩过这个坑**：这样算出来的「送」（第一部·仄声）被当成平声，词谱自己例词的出律率虚高到 29.8%，修正后降到 0.1%。

押韵看**韵部**（同一部即押韵），平仄看**字音条目的声调**。这正是词区别于诗的地方：词的韵部跨声调，诗（平水韵）的韵部按声调划开。

### 字音

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 字 | 是 | |
| 平仄 | 是 | 平 / 仄 |
| 韵部引用 | 是 | |
| 读法标签 | **否** | 韵书自定。词林正韵无信息量可省略；中华新韵填拼音（zhōng / zhòng），是区分同一韵部内多读法的唯一依据 |

**字音是独立实体，韵书是它的容器**——`韵书 → 字 → 字音[]`。切换韵书的语义是「换一套判定依据」，不是「加一个过滤条件」。引擎在构造时绑定韵书，内部**没有韵书分支**。

**读法标签是「待定」态的必要数据**：多音字判不出时，界面须展示「读 zhōng 时是平声、读 zhòng 时是仄声」。只存平仄集合就只能显示「可平可仄」——用户无法据此改字，这个提示是废的。

**双向查询**：底层只存 `韵部 → 字`（韵书的原生形态，也是产物紧凑的前提）；`字 → 字音[]` 的反查索引在加载时构建。两个方向都写进产物是同一份数据存两遍，没有信息增量。

### 校验结果

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 候选 | 是 | **有序**的候选词格列表，按匹配度排序 |
| 选中 | 是 | 被选中的词格 |
| 字位结果 | 是 | 有序。**长度恒等于选中词格的字位数** |
| 整篇摘要 | 是 | 见下 |

**候选列表**：44.7% 的词牌存在「同字数多词格」，用户通常只输入词牌名、不会指明第几体。**选错词格＝给出错误的校验结果**，这是正确性问题。

「多个体都合律」是真实情况，结果必须暴露候选，否则用户会误以为自己的词「就是那个体」。

**引擎接受「词牌」或「词格」两种粒度**：给词格则直接校验；给词牌则遍历该词牌全部词格按匹配度排序。**匹配是逐位判定的副产品**（出律字数最少者胜），不需要单独一次计算。L4 自动辨谱复用同一份代码，只是输入范围扩到全部词格。

**决胜规则**（匹配度相同时必须确定性择一）：

```
① 出律字数少者优先
② 平手 → 正体优先
③ 再平手 → 同字数内序号小者优先
```

**字数不足时的退化**：匹配的筛选条件是「词格字数 == 输入字数」。用户填到一半时无候选可比，此时**不做自动匹配，用正体**。

### 字位结果

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| 字位引用 | 是 | |
| 平仄要求 | 是 | **无论是否已填都携带**——填词的核心价值就是告诉用户这一位该平还是该仄 |
| 句读标记 | 是 | 同上 |
| 字位内容 | 是 | 未填 / 缺字 / 已填某字 |
| 判定态 | 仅「已填」时 | 合 / 出律 / 待定 |
| 可选字音 | 仅「待定」时 | 该字可选读音集合 |

**数组长度恒等于词格字位数**，UI 按位渲染无需条件分支；词谱谱式与用户输入天然同位次对齐，用户可以逐位对照着填。

### 整篇摘要

| 字段 | 说明 |
| :--- | :--- |
| 整体结论 | 合律 / 出律 / 无法判定 |
| 出律字数 / 待定字数 / 缺字字数 / 未填字数 | 各计数 |
| 输入字数 / 词格字数 | 用于字数超出的提示 |
| 韵部情况 | **按片分组**：该片韵部名、韵脚列表（位次 + 字 + 韵部）、是否换韵 |

**韵部情况必须按片分组**：词的押韵规则因体而异（平韵格、仄韵格、换韵格、通叶格、错叶格）。只给「全篇用了哪些韵部」无法回答用户最关心的问题——「我这一片押对了吗」。

**换韵点由词格的「换」标记决定，不由前后片韵部是否相同推断**——通叶格里相邻片可以押相邻韵部，形态上与换韵相似。

## 五、派生量与存储量的边界

**派生量不入存储**，避免两处不同步。以下均为派生：

| 派生量 | 派生方式 |
| :--- | :--- |
| 词作的字序列 | 从原样字符串剥离标点与空白。纯函数，属文本归一化职责 |
| 片边界 | 从词格的换片标记与每片字数推导 |
| 句读位置 | 从词格的句读标记推导 |
| 字音反查索引 | 从韵部方向构建 |
| 字位数 | 从字位序列复算 |
| 是否正体 | 取自原典体例（第一个词格），不在数据中另存标记 |

引擎与检索**消费同一份派生逻辑**（文本归一化），不得各自实现。
