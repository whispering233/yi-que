## A 地基

### 卡 1 · 应用脚手架 + UI 基座 spike + 首次部署

**目标**：站点能构建、能上线，且 antd 样式在静态导出下完整。**这是全项目风险最高的一步**——antd v6 用 CSS-in-JS，在 Next.js App Router 且启用静态导出时样式能否被构建期完整抽取**尚未验证**。若不通过，UI 基座须更换，此时返工成本最低。

- [x] Next.js（App Router，静态导出）+ TypeScript + Tailwind + antd v6
- [x] `AntdRegistry` 包裹 RootLayout
- [x] 路径前缀由构建配置从 `NEXT_PUBLIC_BASE_PATH` 消费
- [x] 一个验证页：antd 组件 + Tailwind 布局 + 三档断点表现
- [ ] 推送后 GitHub Pages 部署跑通（`deploy.yml` 生效）　**阻塞：仓库尚无远程**

**验证**：构建产物中 antd 样式完整（非无样式裸 DOM）；`curl -H 'Accept-Encoding: br' -I <url>` 确认压缩算法
**文档**：`architecture.md`、`build.md`

### 卡 2 · 设计令牌与断点单一来源

**目标**：颜色与排版只有一个来源，断点只有一个定义处。

- [ ] `DESIGN.md` 的令牌落进 antd token 体系（ConfigProvider 覆盖 seed 与组件 token）
- [ ] Tailwind 只管布局：不出现具体色值与字号
- [ ] 断点常量单一定义，Tailwind `screens` 与 antd 响应式配置均从此派生
- [ ] 一个对照页验证：改令牌一处生效、断点两处不漂移

**验证**：改动令牌单一来源，页面所有引用处同步变化；断言两套断点取值相等
**文档**：`ui/DESIGN.md`、`config.md`

### 卡 3 · 领域类型定义

**目标**：`schema` 包成为领域类型的唯一来源。

- [ ] 词牌、词格、字位、词作、词人、韵书、韵部、字音、校验结果、字位结果、候选词格
- [ ] 两层形态的类型：存储形态（紧凑编码）+ 领域形态
- [ ] 两个正交维度（字位内容 / 判定态）以类型表达，**判定态恒为三值**

**验证**：类型可编译；`core` 引用 `schema` 时不引入任何框架依赖
**文档**：`40-data-model.md`

## B 数据管道

### 卡 4 · 管道骨架与护栏框架

**目标**：上游数据能拉取、能产出产物，且护栏不通过即构建失败。

- [ ] 上游数据获取（不入版本控制，见 `.gitignore`）
- [ ] 护栏自检框架：任一项不通过即失败，**不得降级为警告**
- [ ] 产物体积预算检查
- [ ] 接入构建流程：管道在应用构建之前运行

**验证**：故意注入一处缺陷，构建须失败；正常数据构建通过
**文档**：`20-corpus-pipeline.md`、`build.md`

### 卡 5 · 词谱清洗与紧凑编码

**目标**：词谱从 18.69MB 原始 JSON 变为前端可消费的紧凑产物。

- [ ] **去重**：字位序列完全重复者剔除（实测 18 处）——**必须在编号之前**
- [ ] **正体标记**：取自原典体例（去重后第一个词格），不由序号或自述推断
- [ ] **编号**：`{词牌 slug}-{字位数}-{同字数内序号}`
- [ ] 紧凑编码：平仄要求与句读标记可逐字符读取，片边界可定位
- [ ] **词格 id 清单入库**，构建时比对，漂移即失败
- [ ] 自述可解析率监控（基线 93.4%，跌破即失败）
- [ ] 零词格词牌（「清平调辞」）排除或标注

**验证**：产物可从编码独立复算字数/句数/韵数，并与可解析的自述一致；id 清单比对通过
**文档**：`20-corpus-pipeline.md`、`40-data-model.md`

### 卡 6 · 词牌名归一化

**目标**：引擎能接手真实语料。归一化映射表是唯一来源。

- [ ] 按分隔符拆分（组合写法「别名·正名」）
- [ ] 别名映射
- [ ] 繁简与异体字归一化
- [ ] 命中率护栏（基线 94.9%，跌破即失败）

**验证**：全宋词词牌命中率达基线；未命中者均属词谱确实未收的调
**文档**：`20-corpus-pipeline.md`

### 卡 7 · 语料清洗

**目标**：上游错误不进产品。

- [ ] 乱码两档处理：能考证的修正；**考证不出的标为缺字**
- [ ] **清洗不得改变字位数**
- [ ] 缺字标记 `⿰` 原样保留
- [ ] 正文为原样字符串；**题名留空**（语料没有题名）
- [ ] 异常字符计数护栏

**验证**：异常字符计数落在白名单内；逐首比对清洗前后字位数不变
**文档**：`20-corpus-pipeline.md`、`40-data-model.md`

### 卡 8 · 韵书自建

**目标**：两本韵书均为自建，规则白盒可核验。

- [ ] 词林正韵：自公有领域原典自建；**源数据重复项去重**（实测 165 字含重复）
- [ ] 中华新韵：由拼音表推导（声调 → 平仄；韵母归并 → 十四韵）
- [ ] 字音条目为独立实体，韵书为容器；读法标签可选
- [ ] 字音反查索引在加载时构建
- [ ] 拼音覆盖率护栏（基线 99.989%）

**验证**：抽验推导结果与韵表一致；覆盖率不低于基线
**文档**：`40-data-model.md`、`research/competitive-analysis.md`

### 卡 9 · 字体子集生成

**目标**：生僻字不渲染成豆腐块，且移动端不下载全量中文字体。

- [ ] 扩展区 fallback 子集（实测 179 个字符）
- [ ] 词谱符号（○ ● ◎ ⊙ ◇ ◆ □ ■）一并纳入
- [ ] 字体源文件不入版本控制；产物体积护栏
- [ ] 平台原生字体栈定义（宋体栈 + 无衬线栈）

**验证**：产物不超过 50KB；渲染验证扩展区字符与词谱符号均非豆腐块
**文档**：`20-corpus-pipeline.md`、`ui/DESIGN.md`

### 卡 10 · slug 生成与唯一性

**目标**：URL 标识稳定且唯一。

- [ ] 词牌、词人 slug 由归一化后名称生成
- [ ] 多音字冲突由**人工指定表**解决；未解决时构建失败
- [ ] 词作使用稳定数字 id（不用 slug）

**验证**：slug 唯一性断言通过；冲突未解决时构建失败
**文档**：`30-web-app.md`、`40-data-model.md`

## C 引擎

### 卡 11 · 格律引擎 L1

**目标**：逐字对谱、韵位判定、句读分段，纯函数、零框架依赖。

- [ ] 逐字对谱（平 / 仄 / 中；中不判定）
- [ ] 韵脚同韵部判定
- [ ] 句读与换片由词格位次决定，**不由输入标点推断**
- [ ] 字序列派生（剥离标点空白），与检索消费同一份
- [ ] **缺字位不产出判定态**，也不计入出律
- [ ] 字位结果数组长度恒等于词格字位数

**验证**：用真实宋词做正确性检查（正体例词须全合律）；`core` 不引用 React/DOM/Next.js
**文档**：`10-prosody-engine.md`、`40-data-model.md`

### 卡 12 · 多音字消歧 L2

**目标**：判不出时诚实降级为「待定」，并给出可选读音。

- [ ] 韵脚约束优先（同片韵脚互相约束）
- [ ] 词组上下文表
- [ ] 单字默认读音兜底
- [ ] **三态语义**：判不出标「待定」，**不得任取一读音判为出律**
- [ ] 待定态携带可选字音集合

**验证**：待定率在真实语料上收敛；待定结果含可选读音
**文档**：`10-prosody-engine.md`

### 卡 13 · 全宋词回归护栏

**目标**：引擎与词谱数据互为验证。

- [ ] 全宋词语料按**词牌统计匹配率**
- [ ] 某词牌大面积无法匹配任何词格 → 判定为引擎或词格数据缺陷
- [ ] 阈值护栏：跌破即失败
- [ ] 缺字位不得计入出律

**验证**：基线统计报告；人为破坏一处词格数据，护栏须报警
**文档**：`10-prosody-engine.md`

### 卡 14 · 变格 L3 与自动辨谱 L4

**目标**：变格由词谱标记驱动；不给词牌时能自动辨谱。

- [ ] L3：换韵 / 通叶 / 错叶 / 叠韵——**消费词谱标记，不为拗句写特例**
- [ ] 换韵点由词格的「换」标记决定，不由前后片韵部是否相同推断
- [ ] L4：遍历词格匹配（与「给词牌」共用同一份代码，只是输入范围不同）
- [ ] 候选列表按匹配度排序；**决胜规则确定性**（出律少 → 正体 → 序号小）
- [ ] 字数不足时退化为用正体，不做自动匹配

**验证**：换韵/通叶/叠韵词牌的分片与韵部约束正确；决胜规则在多候选下确定性
**文档**：`10-prosody-engine.md`、`40-data-model.md`

### 卡 16 · 校验页

**目标**：产品的核心体验。

- [ ] 填词流程：选词牌 → 列词格（默认正体）→ 录入 → 逐字实时校验
- [ ] 字块：携带词格要求与判定态；**未填与缺字仍显示词格要求**
- [ ] **点击任一字块展示详情**（平仄、韵部、可选读音、释义）
- [ ] 三态与输入状态视觉可区分：出律 / 待定 / 缺字 / 未填
- [ ] 按句读断行；触摸目标不小于 44×44px
- [ ] 整段输入后即时校验，**不做逐字输入格**

**验证**：移动端实测操作流畅；四类状态视觉可区分；出律不靠色相单独区分
