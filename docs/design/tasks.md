## A 地基

### 卡 2 · 设计令牌与断点单一来源

**目标**：颜色与排版只有一个来源，断点只有一个定义处。

- [x] `DESIGN.md` 的令牌落进 antd token 体系（ConfigProvider 覆盖 seed token）
- [x] Tailwind 只管布局：不出现具体色值与字号
- [x] 断点常量单一定义（`tokens.ts`）；Tailwind 的 `@theme` 为镜像，一致性由护栏测试断言
- [x] **禁用 antd 的响应式 API**——其断点硬编码为 576/768/992/1200 且无法覆盖（实测）
- [x] JS 侧 `useBreakpoint` 消费同一常量（自建，因 antd 的 `useBreakpoint` 取值不一致）
- [x] 对照页：令牌单点生效、断点两行始终一致（四个视口交叉验证）

**验证**：故意改 `globals.css` 的断点值，护栏测试必须失败；四个视口的 Tailwind 与 JS 判定必须同档
**文档**：`ui/DESIGN.md`、`config.md`、`architecture.md`

### 卡 3 · 领域类型定义

**目标**：`schema` 包成为领域类型的唯一来源。

- [x] 词牌、词格、字位、词作、词人、韵书、韵部、字音、校验结果、字位结果、候选词格
- [x] 两层形态的类型：存储形态（紧凑编码，带 brand）+ 领域形态
- [x] 两个正交维度以**判别联合**表达：判定态只可能出现在「已填」的字位上，可选字音只可能出现在「待定」上
- [x] 封闭集合导出为运行时常量（`VERDICTS` / `SLOT_CONTENT_KINDS` / `CONCLUSIONS` / `TONE_REQUIREMENTS` / `RHYTHM_MARKS`）
- [x] 机械护栏：断言判定态恒为三值、与字位内容不重叠；断言包内**只能有相对导入**（不得依赖框架或运行时环境）
- [x] 显式 `.ts` 扩展名使本包可被裸 Node 加载（卡 4 的管道需要）

**验证**：`pnpm test` 6/6；故意让 schema 引用 antd，护栏必须失败（已验证）；裸 Node 加载本包成功，只有 5 个运行时值，其余均为编译期类型
**文档**：`40-data-model.md`

## B 数据管道

### 卡 4 · 管道骨架与护栏框架

**目标**：上游数据能拉取、能产出产物，且护栏不通过即构建失败。

- [x] 上游登记表：**锁定提交**（不是分支）+ 大小 + sha256；已登记语料与拼音两个源
- [x] 上游获取：**多镜像顺序回退**（raw → jsDelivr）、重试与超时、**校验失败不重试**
- [x] 护栏框架：先收齐全部结果再抛（一次看到所有问题），**不降级为警告**
- [x] 产物体积预算检查（gzip；只检查实际存在的产物）
- [x] 接入构建：`pnpm build` = `pnpm build:corpus && next build`
- [x] 产物：`meta.json`（来源与版本清单，供站点标注第三方来源——AGPL 义务）

**验证**：注入两处缺陷（收紧词作数预期、篡改登记表大小），构建均以退出码 1 失败；还原后 3 项护栏全过
**文档**：`20-corpus-pipeline.md`、`build.md`

### 卡 5 · 词谱清洗与紧凑编码

**目标**：词谱从原典誊录变为前端可消费的紧凑产物。

- [x] **词谱源选型**：`hulbji/couyun`（MIT，原典誊录），弃用无许可与上游为商业站的候选
- [x] **去重**：按字位序列剔除重复；实测 couyun 数据**无重复**
- [x] **正体标记**：取自原典体例（去重后第一个词格），不由序号或自述推断
- [x] **编号**：`{词牌 slug}-{字位数}-{同字数内序号}`
- [x] **紧凑编码**：每字位 1–2 字符（平仄 + 可选句读标记 + 换片标记 `|`）
- [x] **词格 id 清单入库**（2294 条），构建期比对——id 消失或指向改变即失败
- [x] 自述可解析率监控（基线 **99.9%**，阈值 99%）与结构复算通过率（**96.7%**，阈值 96%）
- [x] 待核清单产物（82 项：复算不一致 75、谱式串脱节 4、自述不可解析 3）

**实测**：817 调 / 2294 体；产物 1088KB 原始 / **114KB gzip**
**验证**：破坏上游词谱数据 → 退出码 1 且 id 护栏报警；还原 → 退出码 0
**文档**：`20-corpus-pipeline.md`、`40-data-model.md`

### 卡 6 · 词牌名归一化

**目标**：引擎能接手真实语料。归一化映射表是唯一来源。

- [x] 按分隔符拆分（组合写法「别名·正名」）
- [x] 别名映射：词谱自带 `names` 表 + 手工补充表（只收有明确词学依据的对应关系）
- [x] 异体字归一化（一翦梅→一剪梅、红林擒近→红林檎近、六么令→六幺令）
- [x] 文体名过滤（失调名、乐语、花舞、采莲舞 等不是词牌）
- [x] **命中率护栏**（基线 **97.9%**，阈值 97.5%，跌破即失败）
- [x] 手工别名的正名不在词谱里时跳过，不制造悬空引用

**验证**：可校验词作命中率 97.9%（20189/20619）；注入不可达阈值后退出码 1，还原后 0
**文档**：`20-corpus-pipeline.md`

- [x] 缺字标记 `⿰` 原样保留（3038 处）

## C 引擎

### 卡 11 · 格律引擎 L1

**目标**：逐字对谱、韵位判定、句读分段，纯函数、零框架依赖。

- [x] 字序列派生（剥离标点空白）；缺字占一个位置
- [x] 逐字对谱（平 / 仄 / 中）——「中」**平凡满足**，判「合」而不是造第四个态
- [x] 韵脚按片分组统计（供界面回答「我这一片押对了吗」）
- [x] 句读与换片由词格位次决定，**不由输入标点推断**
- [x] **缺字不产出判定态**，也不计入出律、不落进待定
- [x] 字位结果数组长度恒等于词格字位数；未填位仍携带词格要求
- [x] 多音字平仄两读 → **待定**（L1 不猜，L2 消歧），且携带全部可选读音
- [x] 机械护栏：core 只能有相对导入（不得依赖 React / DOM / Next / Node API）

**实测验证**（用词谱自己的例词——词格就是从它们归纳的，应全合律）：

```
抽验 772 个词牌的例词｜零出律 743 个（96.2%）
合计 24401 字位｜出律 34（0.1%）｜待定 2030（8.3%）
```

**这条验证抓到一个真 bug**：韵部曾被赋予单一声调，实测出律率虚高到 29.8%。
修正（声调归字音条目而非韵部）后降到 0.1%。

**验证**：92 项测试全过；类型检查与 lint 无警告
**文档**：`10-prosody-engine.md`、`40-data-model.md`

### 卡 12 · 多音字 L2

**目标**：多音字不制造噪音，也不制造错误的出律。

- [x] **定案规则：存在一个满足要求的读音即判「合」**——确定的事实，不是猜测
- [x] 出律只在**所有**读音都不满足时才给——**不任取一个读音判出律**
- [x] **待定的触发条件收窄为「韵书里查不到该字」**——数据里没有，而非猜不出
- [x] 韵脚约束：确定韵脚字属于哪个韵部（供「我这一片押对了吗」），不复用于判平仄
- [x] 不做词组表与默认读音——那是在猜，猜错会制造错误的出律

**实测**（词谱自己的例词，772 个词牌 / 24401 字位）：

```
待定率  8.3% → 1.08%   （多音字不再是待定的理由）
出律率  0.14%
零出律的词牌 743/772（96.2%）
```

剩余待定字全是在韵书里查不到的字（閒 纥 諠 佾 砧 裛…），多为异体字与生僻字。
**验证**：93 项测试全过
**文档**：`10-prosody-engine.md`、`40-data-model.md`

### 卡 13 · 全宋词回归护栏

**目标**：引擎与词谱数据互为验证。

- [x] `src/corpus/decode.ts`：产物 → 领域对象的加载器（唯一知道编码格式的地方）
- [x] 回归：21050 首全宋词跑引擎，按词牌统计
- [x] 判据不是「全部合律」（宋词出律是常态），而是**按词牌统计异常**
- [x] 五条护栏：零出律词作数、无词牌数、无同字数词格数、严重偏离数、可疑词牌数
- [x] 缺字不参与判定（卡 11 已保证）
- [x] **顺带补了编码缺口**：`encodeSlots` 原先没编码**换片标记**，片边界无法定位

**实测基线**：零出律 8276/21050（39.3%）｜匹配率 ≤5% 12605｜出律率 >50% 仅 17 首｜可疑词牌 118

**三处已知数据问题**（不是引擎缺陷，记入 backlog）：861 首无词牌、5265 首无同字数词格（其中 2574 首与最近词格只差 1 字——**语料丢了字**）、47.6% 的词作有出律（宋词常态）

**验证**：破坏上游词谱数据（洞仙歌正体 中→仄）→ 退出码 1 且 id 护栏报警；还原 → 退出码 0
**文档**：`10-prosody-engine.md`

### 卡 14 · 变格 L3 与自动辨谱 L4

**目标**：变格由词谱标记驱动；不给词牌时能自动辨谱。

- [x] L3：消费词谱的句读标记，**不为拗句写特例**
- [x] **韵段 ≠ 片**：韵部约束按韵段，分片按换片标记。韵段边界由**平仄要求类型的变化** +「换」标记共同决定
- [x] 「叶」是通叶，**不切段**——西江月正是这种
- [x] L4：字数筛选 + 逐格匹配；与「给词牌」**共用同一份代码**，只是输入范围不同
- [x] 候选列表按匹配度排序；**决胜规则确定性**（出律少 → 正体 → 序号小）
- [x] 序号**按数值比**——字符串比会让 `-44-10` 排在 `-44-2` 前面
- [x] 字数不足时退化为用正体，不做自动匹配

**实测韵段切分**：菩萨蛮 2/2/2/2（4 段 2 换）｜清平乐 4/3（2 段 0 换）｜西江月 6（通叶不切段）｜定风波 7 段（错叶格）
**实测辨谱**：抹掉词牌让引擎自辨，浣溪沙/如梦令/念奴娇/西江月/清平乐 全部命中
**验证**：103 项测试全过
**文档**：`10-prosody-engine.md`、`40-data-model.md`

```

body 底色 rgb(253,252,250) 宣纸白 · 正文 rgb(31,30,28) 墨 ✓
触摸目标 0 违规 ✓
```

**抓到一个模型缺陷**：`decodeSlots` 把没有句读标记的字位**默认成「句」**，导致每个字位都被当成句末、整首词断成每字一行。根因是模型——字位要么有标记要么没有，**不该有默认值**。`Slot.rhythm` 改为可选。

**另一处**：界面骨架色原先用 antd 的 `--ant-*` 变量做别名层，但那些变量**只在 `.css-var-*` 作用域类里生效**（不是 `:root`，也不是公开 API），`body` 在作用域之外取不到值。改为与断点/字体/五态色同一模式：值来自 `tokens.ts`，CSS 写镜像，**护栏断言一致**。

**验证**：105 项测试、38 项护栏全过
**文档**：`30-web-app.md`、`ui/DESIGN.md`、`40-data-model.md`

**两处产物体积问题**（都是实测发现，都会阻塞部署）：

1. **RSC 预取载荷**：Next 为**每个路由**生成 `__next.*.txt` 与 `index.txt`——23438 个路由下 **93740 个文件 / 734MB**。内容站不需要客户端导航，加 `scripts/clean-export.ts` 清理

**实测**：产物 **2.4GB → 571MB**；词作页 **39KB → 19KB（gzip 4.4KB）**
