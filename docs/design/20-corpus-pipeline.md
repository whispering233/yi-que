# 数据管道设计

管道在**构建期**运行，把上游原始数据转换为前端可直接消费的静态产物。它是构建流程的一环，不进运行时打包。

上游数据都来自第三方，已知含乱码、缺字标记与格式不一致。**管道的首要职责不是转换，而是不让上游的错误进入产品。**

## 上游数据源

| 用途 | 数据源 | 许可 | 备注 |
| :--- | :--- | :--- | :--- |
| 词谱 | 《钦定词谱》（清康熙五十四年官修） | 公有领域 | 818 调 / 2475 体。最干净的基线 |
| 词谱别名词表 | 钦定词谱数字化的别名表 | 需核实 | 仅用作别名映射参考，须核验后使用 |
| 词作文本 | 修订版全宋词（持续校勘） | MIT | 21050 首 / 1564 词人 |
| 拼音 | Unicode Unihan `kMandarin` 派生的拼音表 | MIT | 44437 字，用于推导中华新韵 |
| 韵书 | 《词林正韵》（清·戈载） | 公有领域 | 自维基文库原典自建 |

### 数据源选择理由

**词谱只用《钦定词谱》**：它是确定的公有领域文献，覆盖全宋词 96.6% 的词作（实测），且是唯一无需处理授权争议的完整谱系。其他通行谱系（如龙榆生《唐宋词格律》）覆盖面严格更小，且整理校勘成果的权属存在争议，起步阶段不引入。

**不采用来源存疑的第三方衍生数据**：社区存在若干把商业网站数据抓取后重发布的词谱/韵书仓库，其自身标注的开源许可无法覆盖上游来源。本项目一律以公有领域原典或明确许可的原始数据自建。

**中华新韵自建而非引用现成 JSON**：新韵是对普通话韵母的归并规则，可由拼音数据推导。自建的好处是规则白盒可核验、可逐条对照韵表，且同一张拼音表能复用于多音字消歧的候选读音集合。实测拼音表对本项目所需真汉字（8795 字）的覆盖率为 **99.989%**（仅缺 1 字，属扩展区）。

## 清洗规则

上游文本的已知缺陷与处理方式：

| 缺陷 | 处理 |
| :--- | :--- |
| 乱码字符 | 上游修订版已修掉大部分（非缺字类乱码由 171 处降至 65 处）。剩余长尾由管道清理，并记入待核清单 |
| 缺字标记 | 上游用 `⿰` 表示缺字。**不得当作正常汉字参与校验**，须在引擎与界面中单独处理 |
| 缺字与原乱码混用 | 采用统一缺字标记的上游版本，避免「缺字」与「真乱码」无法区分 |
| 词牌名分隔符 | 上游组合写法用固定分隔符连接别名与正名，须统一 |
| 词牌名繁简/异体字 | 须归一化（详见下节） |
| 词牌介绍混入正文 | 采用已剥离词牌介绍的上游版本 |

### 词牌名归一化

这是引擎能接手真实语料的前提。实测归一化前后差距显著：

| 阶段 | 词牌命中 | 词作命中 |
| :--- | :--- | :--- |
| 归一化前 | 648 / 1421（45.6%） | 84.3% |
| 归一化后 | 1177 / 1421（82.8%） | 94.9% |

排除无词牌的残句（「失调名」372 首）后，可校验词作的覆盖率为 **96.6%**。剩余长尾均为《钦定词谱》确实未收的调，每调仅 1–22 首。

归一化按以下顺序尝试，任一命中即止：

1. **按分隔符拆分**——上游用「别名・正名」的组合写法（如「望江南・忆江南」「酹江月・念奴娇」「金缕曲・贺新郎」）。逐段尝试匹配。**这一条贡献了最大的增量**
2. **别名映射**——词牌别名表（如贺新郎 = 乳燕飞 / 金缕曲 / 貂裘换酒 / 贺新凉）
3. **繁简与异体字归一化**——如一翦梅→一剪梅、六么令→六幺令

映射表是**唯一来源**：引擎、检索、页面生成均消费同一份，不得各自实现。

## 紧凑编码

上游词谱数据把每个字位表示为一个独立对象，产生大量重复键名。实测：

```
上游原始 JSON          18.69MB
  gzip -9               581KB
  brotli q11            386KB
```

原始体积是纯冗余——每个字位携带的信息只有平仄与句读标记两项。前端不应解析这种结构。

**编码目标**：把词格压成字符串，字符本身承载信息，解析退化为字符串遍历。

编码须满足：

- 平仄要求与句读标记可逐字符读取，无需查表或建立索引
- 片边界可直接定位
- 词格的自述信息（字数、句数、韵数）可从中**独立复算**——这是护栏自检的依据

## 管道护栏

**产物写出前强制执行自检，任一不通过即构建失败。** 上游错误不得静默进入产品。

| 检查项 | 判据 |
| :--- | :--- |
| 词格结构一致性 | 从编码复算的字数、句数、韵数须与词格自述一致（如「双调九十五字，前段九句四平韵，后段十句四平韵」）。已手工验证此法可行 |
| 词牌 slug 唯一性 | 818 个词牌的拼音 slug 不得冲突。多音字词牌须在人工指定表中显式给定，不得静默回退 |
| 词人 slug 唯一性 | 同上 |
| 缺字与异常字符计数 | 须落在已知白名单内。计数上升说明上游引入新缺陷或清洗规则失效 |
| 词牌名命中率 | 归一化后的命中率不得低于阈值。跌破阈值说明上游改了词牌名格式或映射表失效 |
| 拼音覆盖率 | 中华新韵所需字集合的覆盖率不得下降 |
| 产物体积预算 | 各产物体积不得超出预算（见下），防止无意引入冗余 |

## 产物清单与体积预算

全部载荷均以 **Brotli** 计量（生产必须开启，对中文的压缩率比 gzip 高 24%–34%）。

| 产物 | 原始 | gzip | **Brotli** | 用途 | 加载时机 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 词谱索引（词牌表 + 别名） | — | 80KB | 约 40KB | 校验页词牌选择 | 首屏 |
| 词谱（全部字位数据） | 18.69MB | 581KB | **386KB** | 校验、辨谱、词谱查询 | 首屏 |
| 词库语料（词作正文 + 词牌 + 词人） | 6.15MB | 2.77MB | **2.08MB** | 检索、词库浏览 | 搜索页懒加载 |
| 词人数据 | — | 20KB | 约 18KB | 词人页、检索 | 词人页 |
| 韵书（词林正韵 + 中华新韵） | — | — | 约 60KB | 引擎判定 | 首屏 |
| 扩展区 fallback 字体 | — | — | **40KB** | 生僻字渲染 | 首屏 |

**首屏总载荷约 530KB。** 词库语料是唯一的重项，且只在进入搜索页时加载一次，之后由浏览器缓存。

### 为什么不分片

语料按词人分片（每 1000 首 Brotli 后约 131KB）理论上可行，但全文检索需要全量语料才能给出完整结果，分片会导致「搜不到已存在的词」。**先做全量加载 + 加载进度提示**；若上线后移动端实测跳出率异常，再改为分片渐进加载——届时检索逻辑在 `corpus` 包内，不与框架耦合，改造面可控。

## 字体子集

中文字体是移动端最大的潜在负担。实测（语料 + 词谱 + 韵书合计 9061 个字符）：

| 方案 | WOFF2 体积 |
| :--- | :--- |
| 全量宋体子集（Noto Serif SC） | 1.9MB |
| 全量黑体子集（Noto Sans SC） | 1.4MB |
| **仅扩展区 fallback 子集** | **40KB** |

**定案：不下载全量中文字体。** 正文用平台原生字体栈，只为系统字体必然缺失的扩展区汉字生成 40KB 微型 fallback 子集。

### fallback 子集的内容

语料与词谱中落在 CJK 扩展 A 区及以上的字符共 179 个（㬠 䰒 䕷 䆉 𠺕 𧣴 㔩 䥏 㫹 䌽 㶁 㶉 䉤 …）。这些字符多数系统中文字体不含，会渲染为豆腐块。

此外须一并纳入：

- **词谱符号**（○ ● ◎ ⊙ ◇ ◆ □ ■）——校验结果与词谱查询的核心视觉元素，其中 `⊙` 等符号并非所有字体都有
- 生僻标点与特殊符号

字体须选择**许可允许嵌入与再分发**的开源宋体（OFL 系）。子集化在构建期由管道产出，源字体不入版本控制。

## slug 生成

词牌与词人使用拼音 slug 作为 URL 标识（URL 契约见 `30-web-app.md`）。

- slug 由归一化后的名称生成，**须稳定**：改名会改变 URL 并损失已收录页面
- **多音字冲突是已知问题**：如「长」「重」作词人姓氏时读音不唯一。冲突须由人工指定表解决，管道在冲突未解决时构建失败
- slug 唯一性检查是护栏的一部分

词作**不使用 slug**，使用稳定数字 id——词作标题会因校勘修订而变动（上游至今仍在校订文本），用 slug 会因改一个字就更换 URL。
