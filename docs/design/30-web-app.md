# Web 应用设计

## 路由与 URL 契约

URL 一旦被搜索引擎收录，改动即损失流量。因此本节的契约**视为冻结**，变更需评估 SEO 影响。

| 路由 | 内容 | 标识方式 |
| :--- | :--- | :--- |
| `/` | 首页，校验入口 | — |
| `/check` | 格律校验 | — |
| `/tune` | 词谱索引（全部词牌） | — |
| `/tune/{slug}` | 词牌详情，含全部词格（正体与变体） | 拼音 slug |
| `/author/{slug}` | 词人详情与其全部作品 | 拼音 slug |
| `/ci/{id}` | 词作详情 | 稳定数字 id |
| `/search` | 词库检索 | 查询参数 |

### 为什么词作用 id 而非 slug

词作标题会因**校勘修订**而变动——上游语料至今仍在校订文本。若用标题生成 slug，改一个字就换 URL，已收录页面全部失效。词牌名与词人名是稳定的，所以它们用 slug；词作必须用 id。

数字 id 不损失 SEO：中文内容站上 URL 的关键词权重低于标题、结构化数据与站内结构，而这三项都由页面负责。

### 拼音 slug 的约束

- 必须稳定（改名即换 URL，损失收录）
- 必须唯一，多音字冲突由人工指定表解决，未解决时构建失败
- 大小写归一（统一小写），分隔符统一

## 页面与取数

| 页面 | 取数方式 | 载荷 |
| :--- | :--- | :--- |
| 首页 | 预渲染 | 词谱索引 |
| 校验 | 预渲染外壳 + 客户端加载词谱 | 词谱 |
| 词谱索引 / 词牌详情 | 预渲染 | 词谱 |
| 词作详情 | 预渲染（每页约 5KB） | 零额外载荷 |
| 词人详情 | 预渲染 | 词人数据 |
| 搜索 | 预渲染外壳 + 客户端加载语料 | 语料（一次性） |

**词作详情页是 SEO 的主力资产**——它提供数千个可被索引的独立内容页，且每页载荷极小。这类页面必须全部预渲染。

## 检索设计

### 索引策略

检索在浏览器内完成。实测三种方案：

| 方案 | 载荷 | 建索引耗时 |
| :--- | :--- | :--- |
| **下发原文 + 运行时建索引** | **2.08MB** | 字级 164ms / 二元 449ms |
| 预建字级倒排索引 | 2.90MB | 0 |
| 预建二元倒排索引 | 5.19MB | 0 |

**定案：不预建索引。** 预建倒排索引的体积反而大于原文（二元组有 47 万个），而下发原文后浏览器建索引只需 449ms。这是所有方案中的最优解。

### 检索能力

| 检索类型 | 说明 |
| :--- | :--- |
| 词句全文 | 匹配词作正文 |
| 词牌 | 含别名匹配，消费归一化映射表 |
| 词人 | 匹配姓名 |
| 组合筛选 | 词牌、词人、字数等条件的组合 |

检索结果须能定位到**匹配的句子**，而非只给出词作标题。

### 加载体验

语料是首屏之外唯一的重项。设计要求：

- 进入搜索页才触发加载，不在首屏预取
- 加载期间显示明确的进度，不得让界面看起来卡死
- 语料是静态资源，浏览器会缓存；二次访问不应重复加载

## 响应式设计

**移动端优先**：默认布局针对手机（单列），随视口增大逐级增强。

### 断点单一来源

项目同时使用 antd 的响应式能力与 Tailwind 的响应式前缀。**两套断点若各自定义必然漂移**，因此：

| 断点 | 宽度 | 布局 |
| :--- | :--- | :--- |
| 基础 | < 640px | 单列（手机） |
| `sm` | ≥ 640px | 单列加宽 |
| `md` | ≥ 768px | 两栏（内容 + 侧栏） |
| `lg` | ≥ 1024px | 三栏 |
| `xl` | ≥ 1280px | 三栏加宽 |

定义只有一处，Tailwind 的 `screens` 与 antd `ConfigProvider` 的响应式配置均从此处派生。

### 移动端特有约束

| 约束 | 说明 |
| :--- | :--- |
| 触摸目标 | 可点击元素的命中区域不得小于 44×44px |
| 移动端侧栏 | 使用抽屉式面板，不用常驻侧栏 |
| 长表格 | 横向滚动 + 粘性首列，或改为窄屏下的竖向序列 |
| 无 hover 依赖 | 任何操作不得只能在 hover 时触达 |
| 输入体验 | 见下节「填词输入」 |

## 交互约束

### 逐字平仄标注的呈现

校验结果是本产品的核心视觉。词作长度可达 95 字以上（如「水调歌头」），在手机宽度下无法单行容纳。

设计要求：

- **按句读断行**，每句独占一行，行内字块自动换行
- 每个字块携带：字、平仄要求、判定态
- **点击任一字块展示该字的详情**：平仄、韵部、可选读音、释义——这是手机上的主要信息获取方式
- 判定态的三值（合 / 出律 / 待定）必须视觉可区分，且「待定」不得呈现为「出律」

### 填词输入：手机上不做逐字输入格

部分同类工具采用「一个字一个输入框」的填词方式。**本项目明确不做**：

- 手机输入法的逐字定位本身就是灾难
- 粘贴整段后即时校验，才是移动端的自然操作
- 逐字格在长调（95 字以上）下会产生极深的滚动

**定案**：整段输入（或粘贴）→ 即时逐字校验并标注。桌面端可选提供逐字定位的辅助能力，但不是主路径。

### 词谱呈现

词谱以符号表示格律（平 / 仄 / 可平可仄 / 韵位 / 句读）。呈现要求：

- 符号与说明图例常驻可见，不依赖记忆
- 窄屏下与校验结果采用一致的断行策略，便于对照
- 符号字形须由 fallback 字体子集覆盖（见 `20-corpus-pipeline.md`）

## 样式系统约束

**不得并存两套样式系统。**

- **Tailwind 只管布局**：flex / gap / grid / 断点 / 尺寸
- **颜色与排版一律走 antd token**，不写具体色值
- 语义色变量映射 antd 的 CSS 变量，不在别处重复定义颜色
- 设计令牌的文档镜像见 `../ui/DESIGN.md`

## SEO

| 项 | 设计 |
| :--- | :--- |
| 预渲染 | 词作、词牌、词人详情页全部构建期预渲染 |
| 标题 | 页面标题须包含词牌、题目、词人 |
| 结构化数据 | 词作页输出结构化元数据 |
| 站点地图 | 构建期生成，覆盖全部词作、词牌、词人页 |
| 规范链接 | 每个内容页有唯一规范 URL，查询参数不产生重复内容 |
| 检索页 | 检索结果页不应被索引 |

## 许可合规

项目以 AGPL-3.0 发布。**网络服务形态下必须为用户提供获取对应源码的入口**——页脚需要常驻的源码链接。这是许可证义务，不是可选装饰。

语料与数据来自第三方开源项目，出处与许可须在站点显著位置标注。
