# 竞品与数据源调研

本文沉淀立项阶段的调研证据。所有体积、覆盖率、性能数字均为**本项目实机实测**，非引用估计值。

## 一、竞品分析

| 平台 | 定位 | 能力 |
| :--- | :--- | :--- |
| **搜韵**（sou-yun.cn，2009 起） | 数据库型 | 收录约 90 万首古今诗词；诗词知识图谱（体裁、用韵、对仗、时间、人物、地理、用典、职官、植物）；格律校验支持《钦定词谱》与龙榆生《唐宋词格律》两种谱系；韵典整合多种工具书；诗词课堂与商城 |
| **诗词吾爱**（2009 起） | 社区创作型 | 中华诗词学会合作平台；格律检测（平水韵 / 词林正韵 / 中华新韵）支持拗救句式；自动笺注与典故分析；个人空间、评论、点赞、擂台赛 |
| 开源同类 | — | 多为毕业设计级项目（Spring Boot + Vue 的通用 CRUD），或纯静态的模型生成式前端，无真正的格律引擎 |

### 竞品的结构性弱点

**格律校验必须提交表单后等待结果。** 两个头部平台的校验都是「输入 → 点开始检测 → 服务端返回结果」的流程，无法做到输入即校验、逐字即反馈。

这个弱点源于架构选择：校验逻辑在服务端，是闭源黑盒。而词谱本身是**公有领域文献**——《钦定词谱》成书于清康熙五十四年（1715）——不存在可保护性，服务端化不带来任何护城河，只带来延迟。

**结论：本项目的立足点是把校验引擎做成纯客户端纯函数。** 逐字实时反馈是体验上的结构性优势，且与 AGPL-3.0 的开放取向自洽。

### 竞品的可借鉴之处

| 能力 | 说明 |
| :--- | :--- |
| 多谱系支持 | 搜韵同时提供《钦定词谱》与龙榆生谱。本项目起步只做前者（理由见下），但引擎须按数据驱动设计以便扩展 |
| 多韵书支持 | 双平台均支持多韵书。本项目起步支持词林正韵 + 中华新韵 |
| 拗救句式识别 | 诗词吾爱支持。本项目在变格层处理 |
| 一字多音的上下文协助 | 搜韵的做法是结合上下文辅助判断多音字平仄。这正是本项目 L2 的设计方向 |
| 自动笺注与典故分析 | 双平台均有。属 L5，本项目后置 |

## 二、数据源调研

### 词谱

| 资源 | 内容 | 许可 | 结论 |
| :--- | :--- | :--- | :--- |
| **《钦定词谱》**（清康熙五十四年官修） | 826 调 / 2360 体（原典所述） | **公有领域** | **采用**。最干净的基线 |
| 社区结构化的钦定词谱数据 | 818 词牌 / 2475 词格 / 195052 个字位（实测） | 标注 MIT，但抓取脚本指向商业网站 | **仅作参考**。上游来源无法被其自身许可覆盖 |
| 钦定词谱网页数字化 | 822 篇 HTML，含平仄符号（○●◎⊙□■◇◆）与别名表 | 仓库无 LICENSE 文件 | 别名表**须核验许可后使用**；不足时以原典自建 |

**词谱只用《钦定词谱》的理由**：

1. **确定的公有领域**——成书于 1715 年，无任何授权争议
2. **覆盖度最高**——实测覆盖全宋词 96.6% 的词作（见下节）
3. **其他谱系覆盖面更小**——龙榆生《唐宋词格律》收词牌 150 余调，是钦定词谱 817 调的子集。作者 1966 年逝世，著作财产权已于 2016 年底届满，但**整理校勘者（张珍怀、龙厦材）的成果权属存在争议**，起步阶段不引入
4. **引擎按数据驱动设计**——加谱系是加数据源，不是改架构，不构成推迟的技术债

### 词作文本

| 资源 | 内容 | 许可 | 结论 |
| :--- | :--- | :--- | :--- |
| 全宋词原始整理版 | 21050 首 / 1563 词人 | MIT | 不采用（见对比） |
| **全宋词修订版** | 21050 首 / 1564 词人，持续校勘至近期 | **MIT** | **采用** |

**实测对比：**

| 项 | 原始整理版 | 修订版 |
| :--- | :--- | :--- |
| 异常字符 | 52 种 / **3241 处** | 35 种 / 3103 处 |
| 缺字标记 | `□` 3070 处 | `⿰` 3038 处，`□` 残留 0 |
| **非缺字类乱码** | **171 处** | **65 处**（少 62%） |
| 词牌分隔符 | 混用 | 统一 |
| 数据组织 | 按 1000 首分片，段落为数组 | 单文件，正文为字符串 |

原始版的乱码实样（会直接显示给用户）：

```
け(35) シ(3) づ(3) ぢ(3) ヵ(3) ホ(2) そ(1) ソ(1)    ← 日文假名残渣
Н(6) ┾(3) ь(2) ㄋ(1) и с б β                       ← 西里尔字母 / 制表符 / 注音符号
```

修订版修掉了这批，残留 65 处长尾（每处出现 1–3 次），由管道清理。

**另一条独立理由**：修订版把缺字统一标记为 `⿰`，而原始版用 `□`——后者与真乱码混在一起，界面无法区分「此处原文缺字」与「此处数据损坏」。

**关于《全宋词》的权属**：通行版本（唐圭璋编，中华书局）的**点校整理成果权属存在争议**。司法实践中法院曾认定点校本构成受保护的法人作品，但法学界对此持反对意见（认为点校是复原原意，不构成演绎）。本项目的文本数据来自网络开源整理版而非中华书局版本，且仅用于展示与检索。此风险已记录，不构成阻塞。

### 韵书

| 韵书 | 韵部 | 许可 | 结论 |
| :--- | :--- | :--- | :--- |
| 《词林正韵》（清·戈载） | 19 部 | **公有领域** | **采用**，自维基文库原典自建 |
| 平水韵 | 5 声部 | **公有领域** | 后置 |
| 中华新韵 | 14 韵 | **自建** | **采用**，由拼音数据推导 |
| 中华通韵（2019 教育部） | 16 韵 | 无现成开源数据 | 后置 |

**中华新韵自建而非引用现成数据**：社区存在现成的新韵 JSON，但**未说明数据来源**，且持有该数据的仓库其他部分存在从商业网站抓取的内容。改用拼音表推导：

- 数据源：Unicode Unihan `kMandarin` 派生的拼音表（MIT，44437 字）
- 推导规则：声调符号（NFD 组合符）→ 声调 → 平仄；剥离声母取韵母 → 归并十四韵
- 规则白盒可核验，可逐条对照韵表

**实测覆盖**：本项目需要判定的真汉字覆盖率为 **100.000%**（缺口 0 字）。

**词林正韵的源数据须去重**：实测**剔除重复项 172 处**（如「冲」「丰」——同一字在同一 `(韵部, 声部)` 组内重复列出）。去重后收 **5037 字**，真正属多个 `(韵部, 声部)` 组合的只有 **153 字（3.0%）**。未去重的计数会把重复项当成多音字，**虚高近一倍**。

推导结果抽验（与韵表一致）：

```
东 dōng → 平 / 十一庚      月 yuè  → 仄 / 三皆      思 sī   → 平 / 十三支
风 fēng → 平 / 十一庚      雪 xuě  → 仄 / 三皆      看 kàn  → 仄 / 八寒，kān → 平
花 huā  → 平 / 一麻        春 chūn → 平 / 九文      斜 xié  → 平 / 三皆
鱼 yú   → 平 / 十二齐      湖 hú   → 平 / 十四姑    柳 liǔ  → 仄 / 七尤
```

**额外收益**：同一张拼音表可复用为多音字消歧的候选读音集合来源。

### 平仄与多音字数据

社区存在平仄表与韵书数据仓库，但实测存在**内部矛盾**：

| 字 | 一份表 | 另一份表 |
| :--- | :--- | :--- |
| 重 | 仄 | 多 |
| 长 | 仄 | 多 |
| 行 | 仄 | 多 |

多音字占比 **8.8%**（728 / 8232 字）。且多音字的韵部信息**不能反推平仄**——《词林正韵》的一个韵部同时含平、上、去声字。

**结论：多音字消歧没有免费的午餐**，只能靠语境（词组表）或语料统计。这是引擎的核心工作量，也是它区别于「查表」的地方。

### 字体

| 方案 | 实测 WOFF2 体积 |
| :--- | :--- |
| 全量宋体子集（Noto Serif SC，9061 字符） | **1.9MB** |
| 全量黑体子集（Noto Sans SC） | 1.4MB |
| 文泉驿正黑子集 | 1.3MB |
| **仅 CJK 扩展 A 区及以上（179 字符）** | **40KB** |

语料与词谱中的扩展区字符（系统中文字体普遍缺失，会渲染为豆腐块）：

```
㬠 䰒 䕷 䆉 𠺕 𧣴 㔩 䥏 㫹 䌽 㶁 㶉 䉤 䰉 䯳 𥱧 䰐 䙀 …
```

**结论：不下载全量中文字体**，用平台原生字体栈 + 40KB 扩展区 fallback。

## 三、覆盖度与体积实测

### 词谱对全宋词的覆盖度

```
全宋词                          21050 首
  └─ 无词牌残句（不可校验）        372 首
  └─ 可校验                     20678 首

词牌名归一化前    648 / 1421 词牌    84.3% 词作
词牌名归一化后   1177 / 1421 词牌    94.9% 词作
                 排除残句后                96.6%
```

**《钦定词谱》817 调覆盖全宋词 96.6% 的词作。** 剩余 3.4% 全是长尾（每调 1–22 首），多为词谱确实未收的调。

### 词牌名归一化的三条规则

实测归一化增量的来源：

1. **组合写法拆分**——上游用「别名・正名」格式（望江南・忆江南、酹江月・念奴娇、金缕曲・贺新郎）。按分隔符拆开逐段尝试。**贡献最大增量**
2. **别名映射**——词牌别名表（贺新郎 = 乳燕飞 / 金缕曲 / 貂裘换酒 / 贺新凉）
3. **繁简与异体字**——一翦梅→一剪梅、六么令→六幺令

### 载荷体积

| 产物 | 原始 | gzip -9 | Brotli q11 | Brotli 相比 gzip |
| :--- | :--- | :--- | :--- | :--- |
| 词谱 | 1.09MB | 115KB | **87KB** | −24% |
| 词谱索引 | 64KB | 14KB | **12KB** | −14% |
| 韵书（两本） | 552KB | 212KB | **133KB** | −37% |
| 词库语料 | 6.93MB | 2.93MB | **2.19MB** | −25% |
| 扩展区 fallback 字体 | 3.8KB | — | **3.8KB** | —（已是压缩格式） |
| **首屏合计（不含语料）** | — | **346KB** | **235KB** | −32% |

**Brotli 对中文的压缩率显著优于 gzip（首屏 −32%，语料 −25%），但当前托管不提供 Brotli**——请求 `br` 返回未压缩内容。载荷预算因此按 gzip 计，可选路径见 `docs/design/backlog.md`。

语料按词人分片可降低单次载荷，但全文检索需要全量语料才能给出完整结果，故起步采用全量加载。

### 客户端检索索引

| 方案 | 原始 | gzip | Brotli | 建索引耗时 |
| :--- | :--- | :--- | :--- | :--- |
| **下发原文 + 运行时建索引** | 6.58MB | **2.86MB** | 2.16MB | 字级 164ms / 二元 449ms |
| 预建字级倒排索引（5192 字） | 7.00MB | 2.89MB | 1.57MB | 0ms |
| 预建二元倒排索引（467692 组） | 13.07MB | 5.12MB | 3.90MB | 0ms |

**结论：不预建索引。** 当前托管只有 gzip——在这个前提下预建索引并不更小（字级与原文持平，二元是原文的 1.8 倍），而运行时建索引只需数百毫秒。（若托管支持 Brotli，字级倒排反而更小：1.57MB vs 2.16MB；届时可重新评估。）

### 词谱数据冗余

上游词谱把每个字位表示为独立对象，产生大量重复键名：

```
字位数据：818 词牌 / 2475 词格 / 195052 个字位
原始 JSON：18.69MB  →  brotli 386KB
```

每个字位携带的信息只有平仄与句读两项，18.69MB 中绝大部分是 JSON 结构开销。前端不应解析这种结构，须转为紧凑编码。

## 四、结论

1. **词谱只用《钦定词谱》**——确定的公有领域，覆盖 96.6% 词作，是唯一无授权争议的完整谱系
2. **词作文本采用修订版**——白得 62% 的乱码修正，缺字标记统一，MIT 许可
3. **韵书全部自建**——公有领域原典 + 拼音表推导，不依赖来源存疑的第三方数据
4. **不做服务端校验**——词谱无保护性，服务端化零收益且损失核心体验
5. **不下载全量中文字体**——1.9MB → 2.2KB，代价是 Android 观感回退
6. **托管须支持 Brotli**——当前托管只提供 gzip，首屏因此多传 111KB（346KB vs 235KB）
7. **多音字消歧是真正的技术难点**——占 8.8%，无免费数据可用，须靠语境或统计
